## 〇、一句话

**扫榜拿到候选 → 填一份清单 JSON → 生成取数脚本 → 交给 Harness 跑 → 出判定报告。**
判定器管**闸门 2（时效）、闸门 3（议论量）、闸门 3-②（发帖人构成）、闸门 1-②（来源表有无网民账号）**；
**闸门 4／5／6／7 一律人判**，工具不碰。

## 二、入口 1：判定新候选（日常主用）

### ★第 0 步：榜面粗筛（★默认该做，2026-10-13 用户定★）

**先粗筛再取数。** 榜单到手**先在榜面上筛**，只把值得跑的拿去取数。
用户原话：**"效率比之前单纯用 skill 慢很多"**——50 条全量双入口取数要跑四五分钟，换来的一半是注定要否掉的条目。

```
node tools\yuqing\scrape.cjs <候选清单.json> --prefilter          # 默认直通位次 ≤20
node tools\yuqing\scrape.cjs <候选清单.json> --prefilter --keep 10
```

**规则**：位次 ≤ `keepRank`（默认 20）**全留**；20 位以后**按议题族去重，每族只留热度最高的一条**。
粗筛后清单落 `tools/yuqing/eval/candidates_prefiltered.json`，**judge 也请用这份**，保证报告与取数一一对应。

**★尺子为什么是位次而不是热度★（实测 50 条社会榜）**

| 该写的条目 | 位次 | 热度 |
|---|---|---|
| 某部委参保扩面动作 | 5 | 799,212 |
| 某教师问责争议 | **15** | **288,878** |
| 某吃播博主健康事件 | **19** | **213,702** |
| 京东00后助浴师 | **29** | **143,467** |
| 某吃播博主健康事件 | **40** | **74,937** |

**该写的条目里 4/5 热度不到 100 万**——按"热度 ≥100 万"筛会全杀掉。
**位次才是尺子**；而同一事件在榜上常有 2—8 条（"某车型制动争议"8 条、"某吃播博主健康事件"5 条），**同族只需判一次**。

**实测效果**：50 条 → **44 条**（"某车型制动争议"族 8 条只留 20 位内 3 条 + 20 位外热度最高 1 条）。

**同族怎么认**（`lib.cjs` 的 `sameTopicFamily`）：
- **强信号**：命中**型号 token**（含数字或 ≥3 字母的拉丁串，如 `V800`）→ 同族
- **弱信号**：≥2 处中文两字重叠 → 同族
- **两个门槛都是踩出来的**：只看 1 处中文重叠 → 「魏家**男子**犯罪集团」误合到「咖啡店…**男子**」；
  只看 ≥2 处 → 某车型制动争议族被拆（因 `V800` 被中文分词滤掉，多数成员只共享「某车型制动争议」一处）

> ⚠ **粗筛只决定"要不要花取数的钱"，不改变判定标准。**被砍的条目照样可以手工加回清单重跑。
> 词条名仍须**与微博逐字一致**。

### 第 1 步 · 扫榜、挑候选

按《共享手册（私有，未随包发布）》第 1 步走——**微博为主**，社会榜／要闻榜。
**记住两条：**
- **词条名必须与微博逐字一致**（含"养老陪伴服务"这类后缀）。用简称会两个入口全空。
- 榜单链接**带 `#`** 的是话题型；**不带 `#`** 的是榜单词条型（后者要额外记热度值和位次）。

### 第 2 步 · 写候选清单 JSON

存到 `tools/yuqing/eval/candidates_<批次名>.json`（示例见 `candidates_board12.json`）：

```json
[
  {
    "name": "某社保欠缴处罚新规",
    "link": "https://s.weibo.com/weibo?q=%23...%23&t=769&Refer=top",
    "matterDate": "2026-10-12",
    "note": "话题型；事情时效由人工提供（央视 10-12 报道）"
  },
  {
    "name": "某部委参保扩面动作",
    "link": "https://s.weibo.com/weibo?q=...&t=769&Refer=top",
    "matterDate": "2026-10-13",
    "hotValue": 2290000,
    "rank": 1,
    "note": "榜单词条型（链接不带 #）"
  }
]
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | **是** | **微博上的词条原文**，逐字一致 |
| `link` | 否 | 榜单原链。带 `%23`（`#`）＝话题型；不带＝榜单词条型 |
| `matterDate` | 否 | **事情时效的人工输入**——权威源原始发布日（如央视报道日）。**目前没自动化** |
| `hotValue` | 否 | 榜单热度值（榜单词条型替代判据用） |
| `rank` | 否 | 在榜位次（同上） |
| `note` | 否 | 备注，会原样带进报告 |

### 第 3 步 · 生成取数脚本

```
node tools\yuqing\scrape.cjs tools\yuqing\eval\candidates_board12.json
```

会在 `tools/yuqing\eval/_run_scrape.mjs` 生成脚本，并打印下一步提示。

> **★为什么不能一步跑完★**：本沙箱**禁止 Node 捕获子进程输出**（stdio 走管道 EPERM、cmd 重定向 stdin "Access is denied"）。
> 所以取数必须由 Harness 托管的 runtime 代跑。详见《开发记录2》第二节。

### 第 4 步 · 跑取数（★三条硬限制，2026-10-13 傍晚 50 条实测得出★）

**限制一：`ego_script` 单次调用有 120 秒硬上限**（`timeoutMs: 300000` 也无效）。
按"一条候选 ≈5.2 秒"算，**一次最多 20 条出头**；超过就**直接超时被杀，且拿不到任何结果**。
→ **候选超过 ~10 条必须分批，每批 ≤7 条。**

**限制二：不要用 PowerShell 管道喂脚本。** 管道会**截断**脚本（报 `Unexpected end of input`），
**用 cmd 输入重定向**：
```powershell
$rt='<用户目录>\.dsh\profiles\desktop\node_modules\dsh-ego-browser\runtime\ego-linux\bin\ego-browser.mjs'
cmd /c "node `"$rt`" < `"tools\yuqing\eval\_run_scrape.mjs`" > `"$env:TEMP\out.txt`" 2>`"$env:TEMP\err.txt`""
```
实测 26 KB 脚本可完整传完（50 条取数 → 13 万字符结果，exit 0）。

**限制三：生成脚本与执行脚本之间必须插一次语法校验。**
```
node --check tools\yuqing\eval\_run_scrape.mjs
```
没这一步，脚本自身的语法错会伪装成 ego 的问题，极难定位。

> **★别用 PowerShell 处理多行脚本★**：`Set-Content -NoNewline` 会把换行吞掉、把 169 行压成一行，
> `//` 注释于是把后面整段代码注释掉。**生成脚本一律用 Node 的 `fs.writeFileSync`。**

**批量推荐的落盘法**（`mk_run_batch.mjs` 已实现，可抄）：
- 用环境变量 `YQ_BATCH`／`YQ_SIZE`／`YQ_LIST`／`YQ_OUTDIR` 控制，**同一个脚本跑多批**，不必每次重新生成
- 结果由脚本内 `await import('node:fs')` **直接写 `_scrape_bN.json`**，**不依赖 stdout**（避免大输出被截断）
- 跑完用 `mk_merge_batches.cjs` 合并 → 喂给 `judge.cjs`

> **ego 运行时里可用的东西（实测）**：`page` 全局可用；**`require` 不可用**（`typeof === 'undefined'`），
> 要用 `await import('node:fs')`；`process.cwd()` 是工作区根目录。

> **BOM 坑**：`judge.cjs` 读 JSON **不容 BOM**。PS 5.1 的 `Set-Content -Encoding UTF8` 会带 BOM，
> 喂给它报 `Unexpected token ''`。改用
> `[System.IO.File]::WriteAllText($p, $s, (New-Object System.Text.UTF8Encoding($false)))`。

### 第 5 步 · 出判定

```
node tools\yuqing\judge.cjs tools\yuqing\eval\candidates_board12.json _judge_board.json
```

> **★取数的两条硬规矩（与耗时无关，必须守）★**
> 1. **必须串行**（脚本内部已串行）。worker 共用同一个 page 对象，并发会互相踩——
>    曾用并发 3 跑 4 条候选，**3 条数据全串成了同一条**。
> 2. **别开多标签页**：`browser.openOrReuseTab` 要写工作区外的 `task-spaces.json`，被沙箱 EPERM 挡住。

产出三样：
- **控制台结论表**（带颜色，逐条列依据）
- `tools/yuqing/eval/last_run.json`（结构化，给下一步用）
- **`判定报告_<日期>.md`**（可留档、可给人看）

### 判定报告长什么样

```
# 选题判定报告（初筛）
## 一、结论一览           ← 一张表：词条／型／事情时效／议论时效／议论量／结论／依据
## 二、逐条明细           ← 每条一节：闸门 2 依据、闸门 3 依据、发帖人构成、失败项
## 三、没被判的闸门        ← ★明写哪些必须人判★（1-①／4／5／6／7）
```

**第三节是这份报告最该看的地方**——它告诉你**工具在哪儿停下来**。

## 三、入口 2：读稿体检（闸门 1-②）

**纯读稿、不联网**，校验"成稿的来源表里有没有网民个人账号原创帖"。

```
node tools\yuqing\judge.cjs --audit-sources
```

输出 53 篇全量报表（来源行数／待核行数／结论／引用到的个人账号），并写 `_audit_sources.json`。

**判据**：来源列须至少一条网民个人账号，**且未被作者标为"须核"**：
1. 显式标签：`网民个人账号`／`个人账号原创（帖）`／`微博个人账号`
2. 本人发帖：`涉事网民本人公开发帖`
3. 直接列举：`微博网民 某微博账号`／`网民"某微博账号"`／`某微博账号、某微博账号等账号转述`

> ⚠ **"网民转述"不算**——那是笼统说法，不是账号。

## 六、★判定器管什么、不管什么★

### 管（可自动）

| 闸门 | 判据 | 数据来源 |
|---|---|---|
| **2 时效** | 拆两条：事情时效（权威源原始发布日）／议论时效（帖子卡片最新时间）。≤2天 新｜3–14天 边缘｜>14天 旧 | 逐卡片帖子时间戳 |
| **3 议论量** | <10 个位数（不论时效直接毙）｜10–999 偏薄｜≥1000 够量 | `topic?q=` 词条卡 |
| **3-② 发帖人构成** | 24h 新帖中普通用户 ≥30% **且** 达人/机构 <50% | 逐卡片作者标识 |
| **1-② 来源表** | 来源列至少一条网民个人账号（纯读稿） | 稿件正文 |

榜单词条型（无讨论量）走**替代判据**：热度值 ≥100 万／位次前 10／24h 新帖 ≥30%，≥2 项命中且密度通过。

### 不管（必须人判）

| 闸门 | 为什么 |
|---|---|
| 1-① 议题真实 | "是不是博主解读"需人判 |
| 4 性质匹配 | 体裁定性需人判 |
| 5 事实有源 | "够不够权威"需人判 |
| **6 落点有接口** | 问的是"**领导能下令干什么**"——政治判断 |
| **7 特别处置** | 问的是"**要不要报**"——**必须领导定，不自决** |

> **实测证据**：`某休假安排议题` 有 **1.1 万讨论／4995.7 万阅读（当日全场最高）**，
> 闸门 2、3 会**必然放行**它——但它的毛病在"区级没有接口"（决定权在国家／省级）。
> **这条正好证明了为什么第六道闸门不能自动化。**

### 已知局限（必须知道）

1. **"普通用户占比"只能当上界看**。微博活跃用户大多带会员标识，
   **分不开"买月费会员的博主"和"普通网民"**（实测"某社保税务处罚口径"的财经博主全被算成普通用户）。
   闸门 3-② 可靠识别的是"**机构+黄V 明确主导（≥50%）**"这一种；**"无认证的博主主导"仍须人判**。
2. **事情时效靠人工喂** `matterDate`，目前没自动化。
3. **"24h 零新帖"是强信号**（`no_fresh`），与"取不到数据"（`nodata`）必须分开——
   曾把前者归成后者，漏掉了一条该拦的稿子。

## 七、文件清单

```
tools/yuqing/
├─ lib.cjs                 纯逻辑层（无网络、无 IO）—— 规则都在这儿
├─ page_scrape.gen.cjs     浏览器侧代码生成器
├─ scrape.cjs              取数入口（生成模式／--pipe）
├─ judge.cjs               判定层（出报告；--audit-sources 读稿体检）
├─ test_lib.cjs            单元测试 164 项
├─ check_generated.cjs     生成器语法自检
├─ eval_frozen16.cjs       历史复核（交接文件 4.2-D）
└─ eval/
   ├─ candidates_*.json         候选清单（评测输入，保留）
   ├─ candidates_frozen16.json  16 条冻结数据（保留）
   └─ _run_scrape.mjs / last_run.json / frozen16_result.json   ← 产物，已 gitignore
```

**改规则只改 `lib.cjs`**（`THRESHOLD` 常量区、各 `gate*` 函数），然后**跑那一套自检**（第五节）。
⚠ **`classifyAuthor` 有两份**——`lib.cjs` 一份、`page_scrape.gen.cjs` 的字符串里一份（页面代码没法 `require`）。
**改分类规则必须两处一起改**；漏改会出现"抓取说 A、判定说 B"的鬼故事。
已由 `check_generated.cjs` **自动对账**（从两边源码抽函数、用 13 个样本逐条比对），**跑一遍就知道有没有漏**。

### 目录命名约定（靠它自动分流进 git）

| 前缀 | 含义 | git |
|---|---|---|

> （里面含真实取数结果）。已改成通配 `_*`，并加 `!mk_*` 反向保留。
