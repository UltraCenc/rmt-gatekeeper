## 一、2026-10-14 起本批修复的（E-01…E-18）

### E-01 单元测试时钟腐坏（7 条断言集体翻红）

| 项 | 内容 |
|---|---|
| **现象** | `test_lib.cjs` 由基线 160/0 变成 **152 通过 / 7 失败**；期望 `write` 的地方返回 `watch`，报错信息完全不指向病因 |
| **根因** | `gate2()` **内部直接写 `Date.now()`**，没有可注入的时钟参数 → 测试想表达"1 天前"只能把日历日期写死（`matterDate:'2026-10-12'`）→ 写就那天＝1.02 天（新），隔夜＝2.04 天（**边缘**）→ 断言过期。**测试自带保质期** |
| **修法** | ① `lib.cjs` 的 `gate2({...}, now = Date.now())`；② `test_lib.cjs` 的 `g2` 传入冻结常量 `NOW`（写死的日期**原样保留**，它们对应真实案例）；③ 文件头写明"本文件涉时刻的断言一律用 `NOW`，不许用 `Date.now()`" |
| **回归断言** | 新增 **7之二** 五条："gate2 收 now（快照当天→新／晚 5 天→边缘）"、"judgeItem 把 now 传给 gate2"、"同一份数据晚 5 天判→待观察"、"matterAgeDays 按传入时钟算" |
| **验证** | 修后 **164 通过 / 0 失败**；再把 `Date.now()` 拨后 7 天复跑，**仍 164/0**（证明与系统日历脱钩） |

### E-02 `judgeItem` 收了 `now` 却没往下传（生产路径的真 bug）

| 项 | 内容 |
|---|---|
| **现象** | 单元测试看不出来；症状是"**用昨天存下来的取数文件判题，事情时效按今天算**" |

| **回归断言** | E-01 的第 3、4 条断言（剪断这根线立刻红） |

### E-07 为压字数砍掉信息（用户当场纠正；★不是代码 bug，是执行纪律★）

| 项 | 内容 |
|---|---|
| **现象** | 当天六篇成稿后做最后压缩，为把 961／837／816 压回 800 以内，**砍掉了四类信息**：①来源限定——"据家属**向媒体**反映"砍成"据家属反映"；②金额构成——"需支付**赔偿金及医疗补助费**共计约11万元"砍成"需赔偿约11万元"；③论据——砍掉一个支撑"考核系提前启动"的时间事实；④落点动作——砍掉"纳入日常检查内容并明确投诉流程"。用户看稿后指出：**"不要为了字数控制而去牺牲语句的流利和表达的意思。"** |
| **根因** | **把优先序搞反了**：先盯"600–800"这个区间，再谈意思，于是压缩时只问"还能删几个字"，没问"删掉的是什么"。**skill 里其实早写着"字数服从内容，不反过来"——规则在，执行时跑偏。** |
| **修法** | ① 四处信息全部恢复（三篇落到 800／817／809，按体例"确有必要可超到 900 左右，超出的每段须是论据或落点"处理，并在各自自检表写明"有意越界"及超出内容）；② `yuqing` skill 字数节加**优先序：意思准确 → 语句流利 → 字数**，以及压缩时的自问"这一刀砍掉的是修饰，还是信息"；③ 手册第 7 步加一张"砍到就恢复"的四类清单，并把本次四处当反面实例挂在上面 |
| **回归** | 脚本测不出来（属内容判断）——**靠两处人工卡口**：手册第 7 步的清单逐句过；自检表里凡超界必须写"有意越界＋超出的是什么"，写不出来就说明是注水或误砍 |
| **注** | 这类错误的价值在于：**它不是"不会写"，是"优先级错了"**——所以修法不是加知识，而是把优先序写成可执行的问句 |

### E-08 读"用户在 Word 里标红"的文件：先确认已保存

| 项 | 内容 |
|---|---|
| **现象** | 用户说桌面那份 docx 已标红，我直接解包却**一个彩色 run 都读不到**；第一次尝试还被 `正由另一进程使用` 拒绝 |
| **根因** | 两层：①**文件被 Word 占用**（同目录 `~$xxx.docx` 锁文件在），默认打开方式被独占锁挡住；②**更关键——标红还在 Word 内存里没落盘**，磁盘上仍是生成时那一版（判据很硬：**字节数与生成时完全一致**，且最后写入时间＝我生成它的时刻） |
| **修法** | ① 只读共享绕过独占锁：`[System.IO.File]::Open($p,'Open','Read','ReadWrite')` 复制一份再解包（**只读，不动用户文件，也不去 kill 他的 Word**）；② 判"有没有标红"看 `word/document.xml` 里的 `<w:color w:val="FF0000">`，同时查有无 `word/comments.xml`（批注是另一种形态）；③ **先比对字节数与生成版**——一致就是"未保存"，直接请用户 Ctrl+S，不要靠猜 |
| **回归** | 手动：解析出的红字**贴回给用户对账**（本次两处与用户所标完全一致）；改完再解包**核验新句在、旧句无、彩色 run 归零** |
| **教训** | 用户说"文件里标了东西"时，**先问一句"保存了吗"比先解析更省事**；但能用字节数/时间戳自己判断，就不要去麻烦用户 |

### E-09 生成脚本给 ZIP 写"当前时刻"，每次重跑都脏 50+ 份 docx

| 项 | 内容 |
|---|---|
| **现象** | `git status` 里常年挂着 50 余份 docx 显示"已修改"，但**尺寸一字不差**（如 4566→4566，共 51 份），正文逐字比对也一致 |
| **根因** | `make_yuqing_docx.ps1` 用 `ZipFile.CreateEntry` 建条目时**没指定时间戳**，.NET 默认写入"当前时刻"→ 每次重跑，7 个条目的时间戳全变 → 字节变 → git 判为修改。**与内容无关，纯噪音。**（查证时还踩了一个自造的坑：用 PowerShell `>` 从 git 取二进制做比对，管道按文本写成 UTF-16，尺寸翻倍，差点误判成"基准件被覆盖"） |
| **修法** | 建条目后钉死：`$entry.LastWriteTime = [DateTimeOffset]::new([DateTime]::new(2026,1,1), [TimeSpan]::FromHours(8))` |
| **回归** | **连跑两次生成脚本、逐文件比对 MD5：0 份不同**（改前 50+ 份不同）——"同样内容产出同样字节"。提交后再跑一次，`git status` 应保持干净 |
| **教训** | 凡"产出物要入库"的生成脚本，**输出必须可重复复现**：时间戳／随机序／绝对路径一律钉成常量。否则每次重跑都制造假改动，**久了就没人看 diff 了** |

### E-10 题目里只放读者不认识的专名（用户当场纠正；执行纪律类）

| 项 | 内容 |
|---|---|
| **现象** | 成稿交付后用户点开问："我如果不知道（这两家机构）是什么，可能看得懂吗"——题目把两个品牌名当主体，对零上下文读者等于两个空洞符号，读完说不出"谁、对谁、做了什么" |
| **根因** | 把"题目可读"默认成了"**我**看得懂"。写题的人知道两家是谁，没做零上下文检验；skill 只写了"读完题目要知道哪里、谁、发生了什么事"，**没有可操作的判据** |
| **修法** | ①该稿题目改身份表述（《某类培训机构抄袭同行试题道歉并赔偿450万元引发网民热议》式），正文①句补身份限定（"某培训机构'甲'就抄袭同行'乙'模拟题…"）；②skill 题目节加硬性条款"**主体必须自解释**"＋判据一句话：**把题目念给不知道这件事的人听，能不能说出谁、对谁、做了什么；说不出就改，不靠正文补救** |
| **回归** | 脚本测不出（专名可读性属内容判断）——人工卡口两道：写题时自念一遍；自检表"题目"一行必须写明"不含读者不认识的专名" |

### E-12 结构化替换吞掉 16 个 $doc 定义（连环两刀，第二刀被断言拦下）

| 项 | 内容 |
|---|---|
| **现象** | ①用临时脚本替换某 $doc 块后重跑生成器，报"无法删除〈工作区根〉"——**定义从 65 掉到 49**（16 个块没了），foreach 引用到空定义；②重写块尾匹配后再跑，护栏报"定义数 57→44"，**拒绝写盘** |
| **根因** | 三层。①**块尾用 `indexOf('\n}\n')` 找**——老块是 CRLF（`\r\n}\r\n`），模式永远匹配不上，一路扫到 16 个块之后我手工插入的 LF 块才命中 → 从起点一路替换到那里；②修补版改成 /\r?\n\}\r?\n/ 却又写了 **`b = a + m.index + …`——`m.index` 本就是全文绝对位置，再加一次 a＝双重偏移**，边界直接飞出十几个块；③两刀都没有在写盘前验结构，第一刀直接落了盘 |
| **修法** | ①块尾一律 /\r?\n\}\r?\n/（**兼容 CRLF／LF 混合——行尾混用是老文件的常态，不是例外**）；②**写盘前断言"结构计数不变"**（$doc 定义数、段落数），不符即拒写；③`git checkout` 回滚前先确认有没有**未提交的独立成果**——本次有两篇成稿的 $doc 块只存在于工作区、不在 git 里，checkout 会连带吞掉；真正的基底是会话前留在 TEMP 的备份（事后已复制进工作区，TEMP 目录按调用切换不可依赖） |
| **回归** | 恢复脚本每步断言（基底 59 → 插片段 65 → foreach → 写盘），终态 Select-String 复核 65 定义、生成 65 份、格式审计全绿；块替换脚本永久带上"定义数不变"断言 |
| **教训** | ①**对入库生成物做脚本化改动，"改完能跑"不算完，"结构计数不变"才算完**——断言这次拦下了第二刀；②验证工具自己也会错（数定义的正则漏一个字符数出 0，让人白绕三步）——**验证脚本要用已知答案对拍，两边不一致先停下查工具**；③一次性 JS 一律落 `.cjs` 文件，不走 `node -e`（PowerShell 会吃引号、展开 `$`），本项目一天栽了三次 |

### E-13 诊断"项目是否被弄坏"时，诊断工具自己三连坑

| 项 | 内容 |
|---|---|
| **现象** | ①用 PowerShell `>` 取 git 二进制做对比，得出"HEAD 版基准件 8414 字节"→ 误报"基准件被生成版覆盖、原件在 git 里"（实际 HEAD 里一直是 4369 字节生成版，8414 是重定向损坏二进制后的假象）；②`git archive -o` 放在 pathspec 之后，被当成 pathspec 报错；③node `spawnSync git` 直接 EPERM（沙箱禁子进程管道） |
| **根因** | ①PS 对外部命令 stdout 做文本解码再编码，二进制必坏——**E-09 里记过一模一样的坑，这是第二次踩**；②③对工具契约不熟，没先查已知限制就开跑 |
| **修法** | git 取二进制一律走 `git archive -o <zip> HEAD -- <文件>`（git 自己写文件，二进制安全；zip 放仓库内）＋ node 解包对比（`_git_extract.cjs`：MD5 → entry 清单/时间戳 → 逐 entry 解压内容） |
| **回归** | 三样本（北大／湖南老人／班主任）对比：**正文 document.xml／styles.xml／core.xml 逐字节一致**，仅 4 个元数据 entry（Content_Types／两处 rels／app.xml）各差 1 字节（换行级，10-14 上午与今日生成环境差异残留）；生成器幂等验证通过（重跑 66 份后 git status 集合不变） |

### E-14 ego 运行时的 cwd 是 profile 目录，相对路径落盘"写成功却找不到"

| 项 | 内容 |
|---|---|
| **现象** | 取数脚本里 `fs.writeFileSync('tools/yuqing/eval/_board_1015h.json', …)` 正常返回，**工作区里没有这个文件**；紧接着 `_print_board.cjs` 报 `ENOENT: no such file or directory`。全盘搜到真实位置：`<用户目录>\.dsh\profiles\desktop\tools\yuqing\eval\_board_1015h.json` |
| **根因** | **ego 运行时注入的 `process.cwd()` 是 profile 目录**（`~\.dsh\profiles\desktop`），**不是工作区根**。手册"三之二"与第六节旧记录写的"`process.cwd()` 是工作区根"**已过期**——运行时／启动方式一变，cwd 就跟着变，照抄文档必栽 |
| **影响** | 本轮丢了一次榜单落盘（数据靠 stdout 与二次抓取补回），**没丢稿**；但这条会让"脚本报写成功、人找不到文件"反复发生 |
| **修法** | ① 脚本落盘**一律写绝对路径**；② 更稳的做法：**脚本只 `console.log`，由 cmd 重定向收走**（本轮取数 45 KB、深翻 60 KB 输出均完整，无截断）；③ 发现落偏后 `Copy-Item` 拷回工作区，并删掉 profile 下的副本，避免两份漂移 |
| **回归断言** | 落盘脚本**末尾加 `if (!fs.existsSync(abs)) throw new Error('落盘路径不在工作区')`**；不落盘的脚本以"stdout 里有 `===标记===`"自证。人工卡口：凡见引号里是相对路径的 `writeFileSync`，一律改成绝对路径 |
| **教训** | **运行时给你一个全局（`page`），不等于给你它的环境。**凡"我写文件"的动作，先问"以谁的身份、在哪个目录写"——`process.cwd()` 要当场打印验证，不要照抄文档 |

### E-15 榜单分类参数写错，服务端不报错、直接回落到默认榜（两个"不同的榜"抓到同一份内容）

| 项 | 内容 |
|---|---|
| **现象** | 按 `https://s.weibo.com/top/summary?cate=social` 与 `…?cate=news` 各抓一次"社会榜／要闻榜"，**两次拿到完全相同的 51 条**（首条都是"深圳全市全天禁鸣喇叭5年"）。两次调用都 `exit 0`、都有数据、页面标题都是"微博搜索-热搜榜"——**长得像抓取成功**，差一点把"两榜重合"当成当日榜面特征写进判定报告 |
| **根因** | 微博榜单的分类参数不是 `social`／`news`。页面上真实存在的 tab 链接是：`summary?cate=socialevent`（社会）／`realtimehot`（热搜，即本项目说的"要闻榜"）／`entrank`（文娱）／`tech`／`life`／`sport`／`game`／`recommend`。**传无效 `cate` 时服务端既不报错也不跳转，直接回落到默认榜**（默认榜恰好就是 `realtimehot`），于是 `social` 与 `news` 这两个无效值给出了同一份内容 |
| **修法** | ① 抓榜前**先从页面自身取真实分类**：`[...document.querySelectorAll('a')].filter(a => /cate=/.test(a.getAttribute('href')||''))`，按可见文字（社会／热搜／文娱…）选，不靠记忆写参数；② 必须写死时按上面这串真实值；③ 本项目口径：**"要闻榜"＝`realtimehot`**（有置顶位、有 `•` 推广位、带 爆/新/热 标），**社会榜＝`socialevent`** |
| **回归断言** | 抓完两榜**立刻断言 `社会榜[0].title !== 要闻榜[0].title`**（两个不同的榜，首条不应相同）；相等即抛"cate 名可能无效，已回落到默认榜"。本轮 `mk_gen_cand_1016.cjs` 另有第二道护栏——候选**按「榜名＋位次」从 `_board_YYYY.json` 精确取**，榜抓错时会在"榜上找不到该位次／词条对不上"处当场炸掉 |
| **教训** | **"接口给了 200 和数据"不等于"给的是你要的那份数据"**——凡是靠字符串参数选资源的接口，都要有一个"选到的确实是它"的自证断言；这次的自证就是"两个榜的第一条不该一样" |

### E-16 ego 脚本里 `import` 语句非法（脚本走 `new AsyncFunction`，是函数体不是模块）

| 项 | 内容 |
|---|---|
| **现象** | 深翻脚本首行写 `import fs from 'node:fs';`，ego 运行时报 `SyntaxError: Cannot use import statement outside a module`；`out=0`、`err=598 字节`，**脚本一个字都没跑**。而同一份脚本早前用 `ego_script` 工具直接发时也不通（当时报的是 `require is not defined`）——**两种导入写法先后各栽一次** |
| **根因** | `require` 与 `import` 都不可用，是**两个不同的原因**：① `require` 不存在——运行时是 ESM 环境，没有 CJS 的 `require`；② `import` **语句**非法——ego 把 stdin 收到的脚本交给 `new AsyncFunction(...)` 执行（`index.js:6750` 的 `execute`），这是**函数体上下文**，而 `import` 语句只允许出现在模块顶层。反证：同一份脚本把首行换成 `const fs = await import('node:fs')` 立刻跑通（动态 `import()` 是表达式，函数体里合法） |
| **修法** | ego 脚本要用 node 内置模块时，**一律用动态导入**：`const fs = await import('node:fs');`（同理 `path`／`url`）；**不写 `import … from`、也不写 `require(…)`**。更稳的替代：脚本干脆**只 `console.log`，由 cmd 重定向收走**（E-14 的推荐做法，也是取数脚本一直在用的方式） |
| **回归断言** | 跑脚本前先看 `_err_*.txt` 是否为空；**已知失败签名表**加两条——`require is not defined` → 改动态 `import()`；`Cannot use import statement outside a module` → 改动态 `import()`。另：脚本落盘时用 `await import('node:fs')` 拿到的 `fs` 上 `writeFileSync`／`existsSync`／`statSync` 均可用，无需别的垫片 |
| **教训** | 同一个"导入不进来"，**两次的病因完全不同**（缺 CJS 全局 vs 语句不在模块顶层）。报错文本不一样就必须当两件事查，**别拿第一个坑的结论去解释第二个坑** |

### E-17 脱敏映射表只认"带 .md 的文件名"，书名号里的内部文档名漏进公开包

| 项 | 内容 |
|---|---|
| **现象** | 重打公开包后，`mk_check_public.cjs` 报**提示 2 处"引用了私有文档"**——定位到 `docs/04-开发记录-独立脚本.md` 与 `docs/06-全流程操作手册.md`，原句是"需并入《工作手册（私有，未随包发布）》"、"日常流程看《工作手册（私有，未随包发布）》"这类**书名号＋简称、不带 `.md`** 的引用 |
| **根因** | `build_public.cjs` 的映射表 11 条内部文档名**全部写死 `\.md`**，只覆盖"文件名"形式；正文里写书名号简称的地方（`《…》`）不是文件名，**正则匹配不到就原样进了公开包** |
| **修法** | ① 11 条内部文档名全部改成 `(\.md)?` 后缀可选（`[/工作手册（私有，未随包发布）(\.md)?/g, …]` 等）；② **同一次还发现漏得更彻底的一批**——新拆出来的三本共享册（`共享手册（私有，未随包发布）`／`取数经验（私有，未随包发布）`／`运营台账（私有，未随包发布）`）**压根没进映射表**（它们是拆册之后才诞生的文件），连 `mk_check_public.cjs` 的 WARN 正则也不认识它们；一并补进映射表（14 条）与检查器 WARN 正则 |
| **回归断言** | 重打后：**自检"引用了私有文档"由 2 处降为 0**；再用一条独立口令扫 `docs/*.md` 里 11 个内部文档名的残留，**结果必须是 0**（第一次修完仍是 2，就是靠这条口令抓出来的）；**"真泄漏 0 命中"全程不变**，剩余提示只有"行业术语 37 处＋文件名模式 2 处" |
| **教训** | **脱敏规则是"防呆"不是"防聪明"**：写规则时人会不自觉地照着"我知道的那个写法"写，而正文里的写法有文件名、书名号、简称、路径等好几种；**更漏的是"新造的文件"——文档结构一变，映射表就少几条，而检查器的正则也是手写的同一份清单，于是两边一起瞎**。规矩：**拆册／改名／建新文件之后，必须回头补映射表与检查器，并用"独立口令扫一遍"验，不能只看检查器自己的结论。** |

### E-18 `python-docx` 默认模板自带缩略图，交付件属性页"保存预览图片"被勾上

| 项 | 内容 |
|---|---|
